# T43 — Prepare Omapresent v0.1.3 (no publication)

**Agent:** `release` · **Spec:** §12, §15 milestone 9 · **Process:**
`pkgbuild/RELEASING.md`

## Why

`v0.1.2` shipped a claim that was not true on the machine it mattered on. Its
notes said embedded players respond to the mouse again, on the strength of
`1cc13bc`, which removed the full-window pointer overlay in the audience
window. That overlay was real and removing it was right, but it was not the
only thing standing between a real mouse and the page: `AudienceWindow.qml`
also carried `activeFocusOnPress: false` on its `WebEngineView`, and Qt
WebEngine's delegate drops the entire pointer stream — hover as much as press —
while the view neither holds active focus nor may take it. So in the released
build the audience window's Play button still did nothing, while the editor
preview, which never set the property, worked.

`c89ad25` removes that second blocker and hands the keyboard back on the
following turn, so keys still reach `Presentation::handleKey` after a click.
That is the one user-visible change since `v0.1.2` and it is what this release
carries.

## Required work

1. Verify every release-note claim against `git log v0.1.2..HEAD` and the tests
   that cover it. Claims that no commit in that range supports are dropped, not
   softened. Say plainly that `v0.1.2` fixed one half of this fault and left
   the other; a release note that quietly re-announces the same fix is worse
   than no note.
2. Bump `pkgver` to `0.1.3` in both PKGBUILDs, keep `pkgrel=1`, and reset the
   source checksum to the 64-zero placeholder. The real checksum cannot exist
   until the tag is pushed, because a tag archive contains the PKGBUILD that
   would hash it — `v0.1.0`, `v0.1.1` and `v0.1.2` all shipped this way.
3. Write `.github/release-notes/v0.1.3.md`. Mention the welcome deck only once
   its new slide really is a slide; a note that advertises a heading which
   renders inside the following slide is worse than no note.
4. Verify the welcome deck edit against real behaviour, not against what it
   says about itself: every claim on the new slide against the feature that
   backs it, and every separator against `DeckModel::isSeparatorLine`. The
   welcome deck is a test fixture — `tests/tst_integration.cpp` pins its slide
   count and its recall-key set — so a deck edit is a change to the suite's
   expectations whether or not it looks like one.
5. Run the full gate from a clean temporary clone of the candidate commit, so
   nothing uncommitted in the shared tree can influence the result:
   `QT_QPA_PLATFORMTHEME= QT_STYLE_OVERRIDE=Fusion ./bin/build` then
   `QT_QPA_PLATFORMTHEME= QT_STYLE_OVERRIDE=Fusion ./bin/test`.
6. Run `pkgbuild/release-checksums self-test`, `bash -n` on both PKGBUILDs, and
   confirm the candidate commit's diff touches owned paths only.
7. Append factual start and finish entries to `worklog.md`.
