# T26 — Publish Omapresent v0.1.1

**Agent:** `release` · **Spec:** §12, §15 milestone 9 · **Process:**
`pkgbuild/RELEASING.md`

## Why

v0.1.0 shipped before two user-visible corrections landed on master:

- `1185b6a` — the audience view is now an independent Wayland top-level, so a
  compositor can share it separately from the editor.
- `48511da` — documents how to start and select that audience window on
  Omarchy/Hyprland without confusing it with the Aquamarine compositor.

Both are in pushed master at `48511da`. They are worth a patch release because
screen sharing an Omapresent deck does not work correctly without them.

## Files you own

- `pkgbuild/PKGBUILD` — `pkgver` only
- `pkgbuild/omarchy-pkgs/omapresent/PKGBUILD` — `pkgver` only
- `.github/release-notes/v0.1.1.md` — new
- `tasks/T26-v0.1.1-release.md` — this file
- `worklog.md` — append only, never rewrite

Do not touch application code, renderer code, tests, or `RELEASING.md`. The
version bump was expected to be the only in-repo change.

**Scope amended during the release.** `.github/workflows/release.yml` is also
owned, for one defect found by running it: the attach step let `gh` infer the
repository from git, and git's dubious-ownership guard aborts on the container
checkout, so the step has never once succeeded — it failed on v0.1.0 and again
on v0.1.1, both times after a clean build and `namcap`. The fix passes `--repo`
and drops `--clobber`.

## Required work

1. Run `./bin/build && ./bin/test` on clean master. Both must be green before
   anything is tagged.
2. Bump `pkgver` to `0.1.1` in both PKGBUILDs and reset the source checksum to
   the zero placeholder. A tag archive contains the PKGBUILD that would hash
   it, so the real checksum cannot exist until after the tag is pushed — this
   is the same order `v0.1.0` used (`10df02f`, then `77cc675`).
3. Write `.github/release-notes/v0.1.1.md`.
4. Commit, then create the annotated tag `v0.1.1` on that commit and push both.
   `v0.1.0` is immutable and must not move.
5. Run `pkgbuild/release-checksums v0.1.1`, commit the result, and push it to
   master before the release is published.
6. Publish the non-draft GitHub release `v0.1.1` from those notes. The Release
   workflow builds the package from the verified PKGBUILD and the immutable tag
   source, runs `namcap`, and attaches the asset.
7. Verify the release URL, tag target, asset name, size and sha256 against the
   built package.

## Not in scope

Omarchy pull request #235 is **not** updated by this task. It is opened against
`omacom/omarchy-pkgs` and carries the v0.1.0 package; pointing it at v0.1.1 is
a separate, later step and needs its own go-ahead.

## Done when

`v0.1.1` exists as an immutable tag on the correct commit, master carries the
matching source checksum, the GitHub release is public and non-draft with the
package attached, and the asset's sha256 is recorded in `worklog.md`.
